!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
ACCURACY CAVEAT
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
  All-time per-model figures above are EXACT: modelUsage carries a real
  four-way split (input / output / cache-read / cache-write).

  Every DAILY figure — the 30d and 7d windows, cost-per-day, and the peak
  day — is an ESTIMATE. dailyModelTokens.tokensByModel is a single fused
  number per model per day: input + output + cacheRead + cacheCreation
  summed together (verified against modelUsage: ratio 1.0000 for every
  model). Recovering a cost from it requires assuming the day had the
  model's all-time average mix. Output tokens cost 50x a cache read, so
  an unusually output-heavy day is understated and a cache-read-heavy
  day is overstated.

  Cache writes are priced at the 5-minute rate (1.25x input) because
  modelUsage does not record the TTL. Claude Code uses 1-hour caching
  (2x input) in places, so this UNDERSTATES the true figure.

  Both approximations disappear if you read ~/.claude/projects/**/*.jsonl
  instead: those records carry a true per-message four-way split AND the
  usage.cache_creation TTL breakdown. Run with --transcripts.
